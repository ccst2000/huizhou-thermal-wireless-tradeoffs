# Thermal–Wireless Trade-Offs of Terrain-Constrained Settlement Morphology in Huizhou Traditional Villages — Reproducibility Package

This repository contains the full analysis code, village-level analysis tables, figure scripts, and
supporting data for the manuscript:

> L. Zhang, *Thermal–Wireless Trade-Offs of Terrain-Constrained Settlement Morphology in Huizhou
> Traditional Villages* (under review).

All inputs are public datasets (Copernicus DEM GLO-30, NASADEM, ESA WorldCover 2021 v200, Landsat 8/9
Collection-2 Level-2 via Microsoft Planetary Computer, Esri World Imagery for Fig. 1 basemap only).
No field data are used. The pipeline is deterministic; the only stochastic steps use fixed seeds
(noted below).

Release **v1.3.0** corresponds to the **v5 analysis chain**: the morphology/terrain metrics are now
*themselves* computed by the fully scripted chain (`s10_morph_terrain.py`, public rasters only), and
four building-fabric metrics (coverage ratio, edge density, patch density, largest-patch share) are
added (`s62_fabric_metrics.py`). Statistical inference uses an explicit dual criterion — within-family
Benjamini–Hochberg q < 0.05 **and** a spatial block-bootstrap 95% CI excluding zero — with exact
cyclic-shift permutation p-values and an effective-sample-size heuristic reported as diagnostics only
(`s41e_stats_v5.py`). Superseded v3/v4 scripts and data are retained under `code/legacy_v3/`,
`data/legacy_v3/`, and flat `*_v4` names for provenance only.

## Repository layout

```
code/        analysis scripts (run order below); legacy_v3/ = superseded scripts
data/        village-level analysis tables, scene manifest, coverage results, statistics JSON
tables/      Tables 1–2 and Appendix Tables A1–A16 (CSV, UTF-8-BOM)
figures/     Figures 1–5 (PNG)
manuscript/  V3_manuscript_full_v5.docx (generated by code/s31d_manuscript_v5.py)
```

Large raster intermediates (30-m UTM DEM/built-up grids, Landsat per-scene stacks, Esri tiles) are
**not** included; they are rebuilt automatically by `s20a_build_grids.py`, `s40_lst_v2.py`, and
`s42_fig1_v4.py` from the public sources above. Public input tiles (Copernicus GLO-30, ESA
WorldCover) are downloaded on demand into `data/external/` by `code/v3_inputs.py` (public S3
buckets; no credentials required). Earlier releases read these tiles from a sibling directory; that
dependency was removed in v1.3.0.

## Grid template

The 100-m UTM50N analysis grid is defined by `data/lst_grid_ref.tif`, produced by
`code/s00_grid_ref.py`. With this release present, the script clones the exact grid of the shipped
`data/lst_summer_median_v4.tif`; in a bare checkout without that file it derives the grid from the
village bounding box (+13 km margin), in which case per-pixel sampling may differ at sub-pixel level
from the shipped results (documented behavior).

```bash
python code/s20b_coverage_v4.py 1250 0 0.7
python code/s20b_coverage_v4.py 0 1250 0.7
python code/s20b_coverage_v4.py 1250 1250 0.7
python code/s20b_coverage_v4.py 0 0 2.6 nocap  # un-truncated NLOS variant (sensitivity), all phases
python code/s20b_coverage_v4.py 1250 0 2.6 nocap
python code/s20b_coverage_v4.py 0 1250 2.6 nocap
python code/s20b_coverage_v4.py 1250 1250 2.6 nocap
python code/s21_phase_aggregate_v4.py      # four-phase village means -> v3_master_v4.csv
python code/s10_morph_terrain.py           # scripted morphology/terrain metrics (PRIMARY chain)
python code/s58_dsm_crosscheck.py          # NASADEM vs COP-DEM cross-check (Table A10)
python code/s62_fabric_metrics.py          # Frame-D building-fabric metrics -> morphology_fabric_v5.csv
python code/s63_master_v5.py               # merge -> v3_master_v5.csv (analysis table of record)
python code/s64_thermal_diagnostics.py     # matching balance (A15), water-mask (A16), LST estimand audit
python code/s41e_stats_v5.py               # dual-criterion inference, permutation diagnostic, ESS
                                           # heuristic, block sensitivity (A14), stats_v5.json,
                                           # Tables 1–2 / A1–A16
python code/s52b_linkbudget_v5.py          # worked link budgets (Table A12)
python code/s42_fig1_v4.py                 # Fig. 1 (downloads Esri World Imagery tiles)
python code/s23_fig234_v5.py               # Figs. 2–4
python code/s22_fig5_v5.py                 # Fig. 5
python code/s60_unit_tests.py              # geometry/metric unit tests (no raster data needed)
python code/s61_morph_robustness.py        # legacy morphology-table comparison (Table A13)
python code/s31d_manuscript_v5.py          # manuscript DOCX (plain single-column layout)
python code/s65_verify_v5.py               # in-text number audit against stats_v5.json
```

A convenience runner `run_all.py` executes these steps in order, skipping products that already
exist (sentinels are real outputs). Expected runtime: ~3–5 h total, dominated by first-run STAC/S3
downloads and the 700-MHz recomputation; all scripts cache downloads and are safe to re-run.

Fixed seeds: overpass-matched ΔLST bootstrap (`seed=7`, B = 10000) in `s56_thermal_v4.py`;
block bootstrap (`seed=11`, B = 2999) and Moran's I (999 permutations) in `s41e_stats_v5.py`.

## Morphology-table provenance (honest statement)

The analysis of record uses `data/v3_master_v5.csv`, whose morphology columns are produced entirely
by scripted chains from public rasters: terrain/landscape metrics by `s10_morph_terrain.py`
(COP-DEM + WorldCover via STAC) and fabric metrics by `s62_fabric_metrics.py` (WorldCover). The
earlier hand-built table `data/morphology_table.csv` (v1–v4 analysis chain) is retained for
provenance; `code/s61_morph_robustness.py` documents the rank-level agreement and sign
preservation between the two chains (`tables/TableA13_morph_robustness.csv`). Two metric families
are definition-sensitive across chains and are flagged in the manuscript: the forest ring (its
component anchor is detectable for all 29 villages only in the extended search window used by s10)
and terrain-horizon openness (tSVF), whose values shift slightly with the window definition.

## Key data files

- `data/v3_master_v5.csv` — 29 villages × sixteen morphological metrics + four performance variables
  (analysis table of record)
- `data/morphology_terrain_v4.csv` — scripted terrain/landscape metrics (`s10`)
- `data/morphology_fabric_v5.csv` — scripted building-fabric metrics (`s62`)
- `data/lst_village_v4.csv` — village overpass-matched ΔLST with bootstrap 95% CI and P(ΔLST > 0)
- `data/lst_abs_village_v4.csv` — village-absolute summer daytime LST
- `data/lst_abs_composite_v5.csv` — estimand audit: composite-raster vs overpass-resolved LST
- `data/dlst_overpass_matrix_v4.csv` — per-village per-overpass matched anomalies
- `data/lst_summer_median_v4.tif` — de-duplicated summer median LST composite (analysis raster)
- `data/lst_grid_ref.tif` — 100-m analysis-grid template (see "Grid template")
- `data/coverage_p*_v4.csv` — per-phase village coverage (`_f0.7` = 700 MHz, `_v4nocap` = no NLOS truncation)
- `data/coverage_4phase_v4[/_f07].csv` — four-phase village coverage, 2.6 GHz / 700 MHz
- `data/thermal_zone_coverage.csv` — LST-zone × coverage joint table
- `data/stations_p*_v4.csv` — per-phase simulated base-station placements
- `data/village_sample_v2.csv` — sample list with per-village coordinate verification status
  (`_draft`/`_v1` retained for provenance)
- `data/lst_scene_manifest.csv` — queried Landsat scenes (invalid/near-zero scenes marked in Appendix)
- `data/wrs_footprints.json` — WRS-2 frame footprints used for scene selection
- `data/stats_v5.json` — every in-text statistic, generated by `s41e_stats_v5.py`, including the
  0.15° block-membership table used by the bootstrap

## Validation

- `CHECKSUMS.sha256` — SHA-256 of every CSV in `data/` and `tables/`; verify with
  `sha256sum -c CHECKSUMS.sha256` (Git Bash/Linux) or equivalent. CSVs are stored with
  `*.csv -text` in `.gitattributes` so checksums are platform-stable.
- `code/s60_unit_tests.py` — unit tests of the geometry/metric primitives (no downloads required).
- `code/s61_morph_robustness.py` — rank-robustness comparison of the legacy and scripted morphology
  chains.
- `code/s65_verify_v5.py` — audits 44 in-text numeric claims of the manuscript against
  `data/stats_v5.json` and `data/v3_master_v5.csv`.

## Known limitations (quoted from the manuscript)

Coverage targets for Zuyuan and Mulihong use a 150-m fallback grid (WorldCover under-detection);
their component anchors shrink to a single detected pixel, and Mulihong additionally lacks Frame-D
plan-form and fabric metrics (n = 28 where applicable). Yuliang's connected component merges with the
adjacent county seat (robustness verified by exclusion). The radio chain is a deterministic
received-power scenario under a stylized deployment, not an operational network estimate. LST is a
summer daytime surface measure, not air temperature or thermal comfort. The matched background (V3)
retains residual imbalance on slope and tree cover for some villages (Table A15).
