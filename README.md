# Thermal–Wireless Trade-Offs of Terrain-Constrained Settlement Morphology in Huizhou Traditional Villages — Reproducibility Package

This repository contains the full analysis code, village-level analysis tables, figure scripts, and
supporting data for the manuscript:

> L. Zhang, *Thermal–Wireless Trade-Offs of Terrain-Constrained Settlement Morphology in Huizhou
> Traditional Villages* (under review).

All inputs are public datasets (Copernicus DEM GLO-30, NASADEM, ESA WorldCover 2020 v100 / 2021 v200,
Landsat 8/9 Collection-2 Level-2 via Microsoft Planetary Computer, Esri World Imagery for Fig. 1
basemap only). No field data are used. The pipeline is deterministic; the only stochastic steps use
fixed seeds (noted below).

Release **v1.4.0** corresponds to the **v6 analysis chain**, rebuilt after a reject-and-resubmit
review round:

- **Single canonical coordinate set** (`data/village_geometry_v6.csv`): village anchors are the
  verified register coordinates, used as published — the earlier snap-to-detected-fabric step is
  removed. Per-village coordinate provenance and canonical-vs-register offsets are audited in
  Appendix Table A11 (max offset 527 m); Kantou and Lixi retain `approximate` flags.
- **Morphology re-instrumented** (`s10b_morph_terrain_v6.py`, `s62b_fabric_metrics_v6.py`): the
  forest ring is the tree-cover fraction of the 500–800-m Euclidean annulus outside the site domain;
  fabric density denominators are the site-domain area; patches are four-connected; tSVF horizon
  angles are truncated at ≥ 0.
- **Inference repaired** (`s41f_stats_v6.py`): the cyclic-shift "permutation" of v5 is replaced by a
  vectorized label-shuffle permutation baseline (B = 9999, seed = 23, non-spatial) and
  Freedman–Lane rank-residual permutation for the partial correlations; the dual criterion
  (within-family BH q < 0.05 **and** spatial block-bootstrap 95% CI excluding zero, B = 2999,
  seed = 11) is unchanged. Appendix Table A14 is unified to B = 2999.
- **Seed-and-design stability audit** (`s41g_a14_mc_stability.py`): every headline interval is
  re-run under 20 seeds × 6 block-design configurations (Appendix Table A14b); seed-sensitive
  pairs are reported as borderline in the text.
- **New sensitivities** (`s66_appendix_tables.py`, `s67_sensitivity_v6.py`): per-village scene
  composition (A8), sampling frame with coordinate audit (A11), WorldCover 2020-vs-2021 vintage and
  day-of-year adjustment (A17).

Superseded v3/v4/v5 scripts and data are retained under `code/legacy_v3/`, `data/legacy_v3/`, flat
`*_v4`/`*_v5` names, and the `LEGACY` list in `run_all.py` for provenance only.

## Repository layout

```
code/        analysis scripts (run order below); legacy_v3/ = superseded scripts
data/        village-level analysis tables, scene manifest, coverage results, statistics JSON
tables/      Tables 1–2 and Appendix Tables A1–A17, A14b (CSV, UTF-8-BOM)
figures/     Figures 1–5 (PNG)
manuscript/  V3_manuscript_full_v6.docx (generated by code/s32_manuscript_v6.py)
```

Large raster intermediates (30-m UTM DEM/built-up grids, Landsat per-scene stacks, Esri tiles) are
**not** included; they are rebuilt automatically by `s20a_build_grids.py`, `s40_lst_v2.py`, and
`s42_fig1_v4.py` from the public sources above. Public input tiles (Copernicus GLO-30, ESA
WorldCover) are downloaded on demand into `data/external/` by `code/v3_inputs.py` (public S3
buckets; no credentials required). The morphology chains (`s10b`, `s62b`, `s67`) stream ESA
WorldCover windows directly from the Microsoft Planetary Computer STAC API at run time.

## Grid template

The 100-m UTM50N analysis grid is defined by `data/lst_grid_ref.tif`, produced by
`code/s00_grid_ref.py`. With this release present, the script clones the exact grid of the shipped
`data/lst_summer_median_v4.tif`; in a bare checkout without that file it derives the grid from the
village bounding box (+13 km margin), in which case per-pixel sampling may differ at sub-pixel level
from the shipped results (documented behavior).

## Environment

- Developed and verified on Python 3.12.4 (Windows 11, x64).
- numpy 2.5.2, pandas 3.0.5, scipy 1.18.0, rasterio 1.5.1, matplotlib 3.11.1,
  python-docx 1.2.0, pystac-client 0.9.0, planetary-computer 1.0.0, pyproj — see
  `requirements.txt`.
- Other platforms: the code is pure Python + GDAL/rasterio and is expected to run on Linux/macOS,
  but binary wheel behavior (rasterio/GDAL) and BLAS threading differ by platform; install the
  pinned versions in `requirements.txt` and treat the shipped CSVs (checksums below) as the
  reference outputs if a numerical discrepancy appears.


A convenience runner `run_all.py` executes these steps in order, skipping products that already
exist (sentinels are real outputs). Expected runtime: ~3–6 h total, dominated by first-run STAC/S3
downloads, the 700-MHz recomputation, and the permutation/bootstrap resampling; all scripts cache
downloads and are safe to re-run. Note the ordering constraint: `s41f` writes `stats_v6.json`
wholesale, while `s41g`, `s64b`, and `s67` append to it (read-modify-write) and must run after it.

Fixed seeds: overpass-matched ΔLST bootstrap (`seed=7`, B = 10000) in `s56_thermal_v4.py`;
block bootstrap (`seed=11`, B = 2999) and Moran's I (999 permutations) plus label-shuffle
permutation baseline (`seed=23`, B = 9999) in `s41f_stats_v6.py`; Monte-Carlo stability
(20 seeds 101–120, B = 999 each) in `s41g_a14_mc_stability.py`.

## Morphology-table provenance (honest statement)

The analysis of record uses `data/v3_master_v6.csv`, whose morphology columns are produced entirely
by scripted chains from public rasters: terrain/landscape metrics by `s10b_morph_terrain_v6.py`
(COP-DEM + WorldCover via STAC) and fabric metrics by `s62b_fabric_metrics_v6.py` (WorldCover). The
earlier hand-built table `data/morphology_table.csv` (v1–v4 analysis chain) is retained for
provenance; `code/s61_morph_robustness.py` documents the rank-level agreement and sign
preservation between the two chains (`tables/TableA13_morph_robustness.csv`). Two metric families
are definition-sensitive across processing versions and are flagged in the manuscript: the forest
ring (association strength depends on how the ring is drawn) and terrain-horizon openness (tSVF),
whose values shift with the window definition and whose headline LST interval is seed-sensitive
(Table A14b).

## Key data files

- `data/v3_master_v6.csv` — 29 villages × sixteen morphological metrics + four performance variables
  (analysis table of record)
- `data/village_geometry_v6.csv` — the single canonical coordinate set with provenance/verification
  flags (`coord_source`, `verified_status`)
- `data/morphology_terrain_v6.csv` / `data/morphology_fabric_v6.csv` — the scripted morphology chains
- `data/lst_village_v4.csv` — village overpass-matched ΔLST with bootstrap 95% CI and P(ΔLST > 0)
- `data/lst_abs_village_v4.csv` — village-absolute summer daytime LST
- `data/lst_abs_composite_v6.csv` — estimand audit: composite-raster vs overpass-resolved LST
- `data/dlst_overpass_matrix_v4.csv` — per-village per-overpass matched anomalies
- `data/lst_summer_median_v4.tif` — de-duplicated summer median LST composite (analysis raster)
- `data/lst_grid_ref.tif` — 100-m analysis-grid template (see "Grid template")
- `data/coverage_p*_v4.csv` — per-phase village coverage (`_f0.7` = 700 MHz, `_v4nocap` = no NLOS truncation)
- `data/coverage_4phase_v4[/_f07].csv` — four-phase village coverage, 2.6 GHz / 700 MHz
- `data/thermal_zone_coverage.csv` — LST-zone × coverage joint table
- `data/stations_p*_v4.csv` — per-phase simulated base-station placements
- `data/village_sample_v2.csv` — sample list with per-village coordinate verification status
  (`_draft`/`_v1` retained for provenance)
- `data/lst_scene_manifest.csv` — queried Landsat scenes (invalid/near-zero scenes marked in Appendix)
- `data/wrs_footprints.json` — WRS-2 frame footprints used for scene selection
- `data/block_membership_0p15.csv` — spatial-block assignments used by the bootstrap
- `data/worldcover_year_compare_v6.csv`, `data/dlst_doy_adjust_v6.csv` — Table A17 underlying data
- `data/stats_v6.json` — every in-text statistic, assembled by `s41f_stats_v6.py` with append
  blocks from `s41g` (Monte-Carlo stability), `s64b` (thermal diagnostics), and `s67` (A17)

## Validation

- `CHECKSUMS.sha256` — SHA-256 of every CSV in `data/` and `tables/`; verify with
  `sha256sum -c CHECKSUMS.sha256` (Git Bash/Linux) or equivalent. CSVs are stored with
  `*.csv -text` in `.gitattributes` so checksums are platform-stable.
- `code/s60_unit_tests.py` — unit tests of the geometry/metric primitives (no downloads required).
- `code/s61_morph_robustness.py` — rank-robustness comparison of the legacy and scripted morphology
  chains.
- `code/s65b_verify_v6.py` — audits 53 in-text numeric claims of the manuscript against
  `data/stats_v6.json` and `data/v3_master_v6.csv` (expected values recomputed from data where
  practical, not hard-coded).

## Known limitations (quoted from the manuscript)

Coverage targets for Zuyuan and Mulihong use a 150-m fallback grid (WorldCover under-detection);
Mulihong has no detected built-up cell inside its domain, so its fabric and plan-form metrics are
undefined (n = 28 where applicable). The built fabric around Yuliang merges with the adjacent
county seat in the land-cover map (robustness verified by exclusion). Kantou and Lixi coordinates
are approximate (flagged in `village_geometry_v6.csv`); excluding both fallback-grid villages
(n = 27) leaves all headline associations in place. The radio chain is a deterministic
received-power scenario under a stylized deployment, not an operational network estimate. LST is a
summer daytime surface measure, not air temperature or thermal comfort. The matched background (V3)
retains residual imbalance on slope and tree cover for some villages (Table A15).
